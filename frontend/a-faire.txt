POUR INFOMANIAK, créer un .htaccess (redirection SPA et sécurité)

# =============================================
# Fichier .htaccess pour Infomaniak
# À placer à la racine de votre hébergement
# =============================================

# 1. ACTIVER LA REÉCRITURE D'URL
RewriteEngine On

# 2. REDIRIGER TOUTES LES REQUÊTES VERS index.html (pour les SPA comme React)
#    Sauf pour :
#    - Les fichiers existants (images, CSS, JS, etc.)
#    - Les requêtes API (vers /api)
RewriteCond %{REQUEST_FILENAME} !-f
RewriteCond %{REQUEST_FILENAME} !-d
RewriteCond %{REQUEST_URI} !^/api [NC]
RewriteRule ^ index.html [L]

# 3. SÉCURITÉ : BLOQUER L'ACCÈS AUX FICHIERS SENSIBLES
<FilesMatch "\.(env|htaccess|htpasswd|ini|log|sh|sql)$">
  Order allow,deny
  Deny from all
</FilesMatch>

# 4. SÉCURITÉ : DÉSACTIVER LE LISTING DES DOSSIERS
Options -Indexes

# 5. CACHE : OPTIMISER LE CACHE POUR LES ASSETS STATIQUES
<IfModule mod_expires.c>
  ExpiresActive On
  ExpiresByType image/jpg "access plus 1 year"
  ExpiresByType image/jpeg "access plus 1 year"
  ExpiresByType image/png "access plus 1 year"
  ExpiresByType image/webp "access plus 1 year"
  ExpiresByType text/css "access plus 1 month"
  ExpiresByType application/javascript "access plus 1 month"
</IfModule>

# 6. COMPRESSION GZIP
<IfModule mod_deflate.c>
  AddOutputFilterByType DEFLATE text/html text/plain text/xml text/css text/javascript application/javascript application/x-javascript
</IfModule>

# 7. TYPES MIME POUR WEBP
AddType image/webp .webp

# 8. HEADERS DE SÉCURITÉ
<IfModule mod_headers.c>
  Header set X-Frame-Options "DENY"
  Header set X-Content-Type-Options "nosniff"
  Header set X-XSS-Protection "1; mode=block"
  Header always set Strict-Transport-Security "max-age=31536000; includeSubDomains; preload"
  Header set Referrer-Policy "strict-origin-when-cross-origin"
  Header set Content-Security-Policy "default-src 'self'; script-src 'self' 'unsafe-inline' 'unsafe-eval'; style-src 'self' 'unsafe-inline'; img-src 'self' data: https:; font-src 'self'; connect-src 'self' https://votre-domaine.com;"
  Header set Feature-Policy "geolocation 'none'; microphone 'none'; camera 'none'; payment 'none'; usb 'none'"
</IfModule>









MESURES DE SÉCURITÉ APPLIQUÉES SUR CE PORTFOLIO :

# 🔒 Mesures de Sécurité Appliquées - Portfolio

## 📌 **Backend (Node.js/Express)**

### 1. **Authentification et Autorisation**
- ✅ **JWT (JSON Web Tokens)** :
  - Tokens signés avec une clé secrète (`JWT_SECRET` dans `.env`).
  - Expiration après 2 heures (`expiresIn: '2h'`).
  - Middleware `auth` pour protéger les routes sensibles (`/api/projects`, `/api/contact`).
  - Vérification du rôle (`admin`) pour les actions critiques.

- ✅ **Stockage sécurisé des identifiants** :
  - `ADMIN_ID` et `ADMIN_PASSWORD` dans `.env` (jamais en dur dans le code).
  - `.env` dans `.gitignore` pour éviter les fuites.

---

### 2. **Protection contre les attaques courantes**

- ✅ **CORS (Cross-Origin Resource Sharing)** :
  - Restreint aux origines autorisées (`FRONTEND_URL` dans `.env`).
  - Méthodes autorisées : `GET`, `POST`, `PUT`.
  - Headers autorisés : `Content-Type`, `Authorization`.

- ✅ **Limite de taille des requêtes** :
  - `express.json({ limit: '10mb' })` pour éviter les attaques DoS via des payloads trop gros.

- ✅ **Uploads de fichiers sécurisés** :
  - **Multer** :
    - Filtre MIME type : seules les images (`image/*`) sont acceptées.
    - Limite de taille : 5 Mo par fichier, 10 fichiers max par requête.
    - Noms de fichiers uniques (timestamp + random) pour éviter les collisions.
  - **Sharp** :
    - Redimensionnement des images à 80% de leur taille originale.
    - Conversion en **WebP** (format moderne, plus léger).
    - Qualité réduite à **80%** pour optimiser la taille sans perte visible.
    - Suppression des fichiers temporaires après traitement.

- ✅ **Headers de sécurité** (via `.htaccess` pour Infomaniak) :
  - `X-Frame-Options: DENY` → Empêche l'inclusion dans des iframes (clickjacking).
  - `X-Content-Type-Options: nosniff` → Empêche le MIME sniffing.
  - `X-XSS-Protection: 1; mode=block` → Active la protection XSS du navigateur.
  - `Strict-Transport-Security` (HSTS) → Force HTTPS pendant 1 an.
  - `Referrer-Policy: strict-origin-when-cross-origin` → Limite les informations envoyées dans le header Referer.
  - `Content-Security-Policy` (CSP) → Restreint les sources autorisées pour les scripts, styles, images, etc.

---

### 3. **Gestion des erreurs**
- ✅ **Middleware `errorHandler`** :
  - Centralisation de la gestion des erreurs.
  - Ne renvoie **jamais** les détails des erreurs en production (seulement en développement).
  - Pour `/api/projects` et `/api/testimonies` : renvoie un tableau vide (`[]`) pour éviter les erreurs côté front (`TypeError: projects.filter is not a function`).

- ✅ **Validation des inputs** :
  - Vérification de la présence des champs obligatoires (ex: `name`, `email`, `message` pour le contact).
  - Vérification de l'existence des projets avant mise à jour (`PUT /api/projects/:id`).

---

### 4. **Sécurité des fichiers**
- ✅ **Permissions** :
  - Le dossier `img/` (à la racine) a les permissions **755** (lecture/écriture pour le propriétaire, lecture/exécution pour les autres).
  - Les fichiers sensibles (`.env`, `.htaccess`) sont **exclus du git** (via `.gitignore`).

- ✅ **Stockage des images** :
  - Les images uploadées sont stockées dans `img/` **à la racine** (pas dans `backend/`).
  - Noms de fichiers uniques pour éviter les écrasements.
  - Conversion en **WebP** pour réduire la taille et améliorer les performances.

---
---

## 🌐 **Frontend (React)**

### 1. **Stockage des tokens**
- ✅ **localStorage** :
  - Le token JWT est stocké dans `localStorage` après connexion.
  - Supprimé à la déconnexion.
  - **Attention** : `localStorage` est vulnérable aux attaques XSS. Pour un site sensible, utiliser `httpOnly` cookies + CSRF tokens.

### 2. **Requêtes API sécurisées**
- ✅ **Headers d'autorisation** :
  - Le token JWT est envoyé dans le header `Authorization: Bearer <token>`.
  - Utilisation de `fetch` avec les headers appropriés.

- ✅ **Gestion des erreurs** :
  - Vérification du status HTTP (`res.ok`).
  - Affichage de messages d'erreur génériques (pas de détails sensibles).

### 3. **Accessibilité (a11y)**
- ✅ **Balises ARIA** :
  - `aria-label` sur tous les boutons et icônes.
  - `aria-modal="true"` sur les modales.
  - `role="dialog"` pour les modales.
  - `aria-hidden="true"` pour les éléments décoratifs (icônes FontAwesome).

- ✅ **Navigation clavier** :
  - `tabIndex` sur les éléments interactifs.
  - Gestion des événements `onKeyDown` pour les actions au clavier (ex: touche Entrée pour valider).

- ✅ **Images** :
  - Balises `alt` descriptives sur toutes les images.
  - `loading="lazy"` pour le lazy loading (améliore les performances).

### 1. **Configuration du serveur**
- ✅ **HTTPS** :
  - Activer le certificat SSL/TLS (gratuit via Let's Encrypt sur Infomaniak).

## 🛡️ **Recommandations Supplémentaires**

1. **Pour un site en production** :
   - Utiliser un **reverse proxy** (Nginx) devant Node.js pour :
     - Gérer le HTTPS.
     - Limiter les requêtes (rate limiting).
     - Bloquer les attaques DDoS.
   - Exemple de configuration Nginx :
     ```nginx
     server {
         listen 443 ssl;
         server_name votre-domaine.com;

         ssl_certificate /path/vers/certificat.crt;
         ssl_certificate_key /path/vers/cle_privee.key;

         location / {
             proxy_pass http://localhost:3001;
             proxy_http_version 1.1;
             proxy_set_header Upgrade \$http_upgrade;
             proxy_set_header Connection 'upgrade';
             proxy_set_header Host \$host;
             proxy_cache_bypass \$http_upgrade;
         }

         location /img/ {
             root /chemin/vers/le/projet/;
             expires 1y;
             add_header Cache-Control "public";
         }
     }
     ```

2. **Monitoring** :
   - Utiliser **Sentry** ou **LogRocket** pour surveiller les erreurs frontend/backend.
   - Configurer des alertes pour les erreurs critiques.

3. **Tests de sécurité** :
   - Effectuer des tests avec **OWASP ZAP** ou **Burp Suite**.
   - Vérifier les vulnérabilités avec `npm audit`.

4. **Bonnes pratiques** :
   - Ne **jamais** commiter de secrets dans Git (utiliser `.gitignore`).
   - Utiliser des **variables d'environnement** pour tout ce qui est sensible.
   - Mettre à jour **régulièrement** les dépendances (`npm update`).
